# Forge AI Assistant roadmap

The roadmap separates public educational progress from the private MFDA Forge
beta. A checked box here never means that private implementation files or
customer data have been published.

## Completed educational foundations

- Hugo learning platform, reusable notices and repository safety checks
- Build with Hermes ZA learning path and plain-language system architecture
- reviewed tutorials for readiness, VPS preparation, Hermes installation,
  model and business-knowledge boundaries, secure tunnelling, WhatsApp Cloud
  API review, scoped tools, testing, operations and recovery
- glossary, security boundaries, prompt guidance and synthetic business example
- sanitised MFDA Forge closed-beta case study
- GitHub Pages build and deployment workflow, subject to project review controls

## Current closed-beta learning and sanitisation

- test Forge privately with MFDA using synthetic and authorised beta scenarios
- record behaviour differences between terminal tests and real WhatsApp messages
- improve trial-request state wording, handover context, maintenance controls,
  audit visibility and safe failure behaviour
- sanitise lessons so they expose patterns without production prompts,
  customer data, private locations, credentials, endpoints, databases or logs
- review every candidate reusable component before public release

## Planned generic reference implementation

- generic Hermes identity and business-knowledge templates
- narrowly scoped example tool and manifest with no production integration
- readable install, verification, backup and rollback scripts
- configuration validation and security review checks
- synthetic acceptance and adversarial test fixtures

These components are planned; their private beta equivalents are not present in
the public repository.

## Independent verification still required

- pin and test supported Hermes versions and configuration formats
- independently reproduce installation and least-privilege configuration
- test webhook, tunnel, messaging and tool boundaries in a non-production setup
- test backup, restoration, rollback, session expiry and maintenance behaviour
- recheck current provider dashboards, policies, limits and requirements before
  any authorised integration exercise
- complete mobile, accessibility and security review of release candidates

## Future public-release milestones

1. Sanitise and owner-review one generic end-to-end example.
2. Independently test its documented commands, verification and rollback.
3. Publish only the reviewed reusable components and synthetic evidence.
4. Mark the version clearly and document remaining limitations.
5. Require human review before any first production use or material change to
   authentication, providers or security controls.

The website is educational, not a hosted assistant service. Copying the guide
does not guarantee a secure or suitable deployment.
